# ADR-0014: run_task_with_nobody（薄 primary + work 分支 + 保绿跳过）

## 日期

2026-08-10

## 状态

已接受

## 背景

`run-tasks`（ADR-0013）在无人值守真实执行中发现：子代理干活，测试与合并却发生在 primary，primary 上下文因无人处理而耗尽。无人值守模式的最大约束不是授权，而是 **primary 的上下文预算**——没有人类在场清上下文。本技能专为无人值守设计：primary 保持薄，子代理全权自治，高危动作（合入 main、关闭议题）整体移出技能。

关键约束：

- 无人值守下没有人类兜底，primary 上下文必须受控；子代理的活必须全部在子代理自己的对话里完成。
- 合入 main 是唯一不可逆高危动作——由技能**结构上保证不碰 main**，而不是靠授权语句兜底。
- 权限系统会拦截未放行的命令；无人值守下拦截 = 停在提示处等一个不存在的人。

## 决策

引入本地技能 `run_task_with_nobody`（`.claude/skills/run_task_with_nobody/`，user-invoked，`disable-model-invocation: true`）。与 `run-tasks`（ADR-0013）**并存**，本技能专为无人值守；触发必须逐字包含「无人值守，授权执行」（技能全程无合并操作）。

### 薄 primary，串行派发

primary 只做六件事：建 work 分支、建依赖图、算前沿、派一个子代理、处理回报（成功/跳过）、写交接。同一时刻至多一个实现子代理（**严格串行**）。子代理回报是**薄报告**（变更列表 + 测试结果 + 提交 sha），不把 full transcript 带回 primary。

### work 分支模型，无合并操作

启动时从 main 建 `work/<父议题>-<NN>` 并 push；所有子代理的变更直接落在该分支，提交一律带 `#<N>:` 前缀（每任务可归因）。技能**全程不执行 `git merge`、不关闭议题**。合入 main 是用户回来后的唯一动作。

### 保绿不变量

work 分支**永远绿，每次 push 都是绿的**。子代理无法保绿时不推送——失败工作提交到本地（带 `#N` 前缀）但不 push。串行下每个子代理都从上一绿点起手，后一个永远站在绿的基线上。

### 两种回报：成功 / 跳过

子代理结局对 primary 只有两种：

- **成功**：绿、push、work 分支出现 `#N` 提交、议题发「已并入」评论。
- **跳过**（🚦 需决策 与 无法推进都算）：一律「本地暂存 `wip/issue-N` + work 分支回滚 + 继续下一个不依赖它的任务」。唯一区别：
  - **🚦 需决策**：不重试——重试没用，缺的是人类的答案。
  - **无法推进**（测试过不了/卡住）：**最多重试一次**（换新子代理 + 简报附失败原因），仍失败才跳过。

### GitHub 为状态事实源

每议题任一时刻处于五态之一，仅凭 GitHub 可重建：**未开始 / 完成（「已并入」评论 + work 分支 #N 提交）/ 等决策（`ready-for-human` + `🚦`，含问题 + 暂存分支名 + sha）/ 卡死（`🚫`，含原因 + 暂存分支名 + sha）/ 进行中**。人类在 🚦 后答复 → 重启该任务，**复用 `wip/issue-N` 暂存分支**（rebase 到当前 tip，继续加 #N 提交）。

### 终局 = 交接

前沿空（可跑任务全做完、只剩被跳过任务卡住的依赖者）时：父议题发交接评论（work 分支名 + `gh pr create` 指令 + 完成/等决策/卡死/连带不可跑分类）。父议题保持开，合入 main 与关闭议题由用户执行。

## 理由与权衡

- **薄 primary vs 全权 primary**：问题根因是 primary 攥着测试与合并；把执行全沉到子代理、回报压成薄报告，primary 上下文与批大小解耦，无人值守可跑很长的批。
- **work 分支 vs 合并进 main**：把合 main 从技能里拿掉，无人值守的爆炸半径降为一次性 work 分支；`git merge`/`gh issue close` 的权限与授权问题整体消失。allowlist `git push` 从高危变成无害（目标只是 work 分支）。
- **保绿 vs 先推局部**：共享 work 分支上，失败的局部提交会污染后续兄弟任务（测试全红互相踩）；保绿让每个子代理永远站在绿的基线上。代价：失败工作可能丢失，靠 🚦/🚫 评论记死暂存名 + sha，重启重做。
- **跳过统一 vs 三态返回**：primary 决策面收敛为二分（成功/跳过），🚦 与无法推进只在"要不要重试"上区分，primary 更薄。
- **本地暂存 vs 推远端**：暂存分支只在本地（远端保持干净），🚦/🚫 评论记死暂存名 + sha——跨机器丢失也能凭交接重做。
- **串行 vs 并行**：保串行。primary 上下文问题的根不是并发；并行反而在共享 work 分支上引入冲突，与"永远绿"冲突。

## 不做什么（Out of Scope）

- 并行前沿执行；值守模式（supervised，用 run-tasks/ADR-0013 或人类在场）；自动合入 main；自动关闭议题；远端暂存分支。
- 子代理再开子代理（自审在自己的对话里）；每任务合并前重复询问（无人值守没人可问）。
