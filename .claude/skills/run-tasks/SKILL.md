# Run Tasks

按依赖顺序执行一批 GitHub 议题（主议题 + 带依赖的子议题），一次派一个实现子代理。目标：尽可能多完成，只在真正的业务决策处停下，把没跑完的留成清晰交接。

上游是 `/grill-me` → `/to-spec` → `/to-tickets`，本技能消费其产物。心智与 to-tickets 对齐：**前沿**（frontier）= 所有阻塞者已关闭的议题；**交接** = 留给下一个代理/人类的路标。底线：**状态以 GitHub 为准**——中断、重跑、跨会话都不丢东西。

## 输入

- **主议题号**（首选）：子议题从依赖图解析。
- **一组议题号**（兜底）：空格/逗号分隔或范围（如 `29..39`），第一个无阻塞者为入口。

两者都给时用主议题。

## 干跑（--plan）

传 `--plan` 或"只看顺序"时**不派任何子代理**：读输入、建依赖图、算前沿，打印执行顺序 + 每个任务的当前状态（按下面的状态模型），然后停。这是合跑前审查、也是安全评估本技能的方式。

## 状态模型（以 GitHub 为准）

每个子议题任一时刻处于恰好一种状态；仅凭 GitHub 可重建：

| 状态 | 可观测特征 |
|---|---|
| 未开始 | 开着，无 WIP 分支，无 `ready-for-human` |
| 进行中 | 开着 + 已推送未合并分支 `feat/issue-N-*` |
| 等待决策 | 开着 + `ready-for-human` + `🚦` 决策评论（问题/选项/分支名） |
| 可续作 | 开着 + `ready-for-human` + `🚦` 之后出现新的人类评论 |
| 完成 | 关闭 + 合并评论 |
| 卡住 | 开着 + `🚫` 卡住评论（原因：环境缺 / 规格矛盾 / 不可能） |

`🚦`/`🚫` 是评论首行的原样标记，grep 即可分类。

## 触发、值守模式与授权（三层闸门，禁止模糊确认）

本技能**只由用户手动触发**（`/run-tasks ...`），不要因"看起来有任务"而自作主张启动。

**第一层 · 值守模式**：动手前先问用户会不会走开——**无人值守只在用户明说会走开时启用**：

- **用户明说会走开** → 无人值守：串行派子代理、按常设授权自动合入、跑不完的交接。
- **用户在场 / 未说会走开** → 值守模式：每个任务合并/关闭前停下等明确授权；问题当场转述、等答复。

**第二层 · 合入/关闭授权**：无论哪种模式，合入与关闭议题都要用户**逐字明确**说出授权语句，例如：

> 满足测试要求的前提下，授权合并、关闭议题。

只有**绑定条件（测试满足）** + **明确动作（授权合并 / 关闭议题）** 的完整语句才算授权。下列**都不算**：单字「y / 好 / 同意 / 确认 / 可以」；无条件「合并吧 / 关掉吧」；含糊「看着办 / 你决定」。拿不准 = 未授权。

**第三层 · 权限边界**：`git merge`、`git push`、`gh issue close` 会经过权限系统。未授权时被拦是预期内的安全网；已授权的无人值守合入要落地，用户需预先 allowlist 这些命令，否则合入停在权限提示处。被权限拦下的合入/关闭，把任务留在 `待合入`、写进终局交接，不原地重试。

## 循环

1. **读输入**：`gh issue view <n> --comments` 拉议题全文，`gh issue list` 枚举子议题。
2. **建依赖图**：解析每个子议题正文的 `Blocked by: #N` 边。
3. **算前沿**：开着 + 阻塞者全关 + 非等待决策 + 非卡住 + 未完成。若存在**可续作**任务，先做它。当前沿为空时进入终局处理。
4. **取一个任务**：严格串行，同一时刻至多一个实现子代理——串行使每个任务从上一任务合并后的 main 起分支，基线平凡、无冲突。多个兄弟任务同时解锁时，按议题体内的 `# NN —` 序数取最前者（无则按议题号），保证跨运行可预测。
5. **派一个子代理**（Agent 工具，命名 `run-task-<N>`，简报模板见下），按启动时确定的值守模式给授权。
6. **处理返回**（完成/待合入/提问/卡住），重算前沿，回到 3。

## 派发简报

把议题全文+评论、任务当前状态、值守模式、验证契约原样交给子代理：

```
实现本仓库的 GitHub issue #<N>。仓库约定见 AGENTS.md。

议题正文与验收标准：
<全文>

当前状态：<未开始 | 分支 feat/issue-N-* 已推送——复用>
值守模式：<无人值守（已授权，测试绿可合入） | 值守（只留待合入，不合入不关闭）>

做：
1. 建分支：远端已有未合并的 `feat/issue-N-*` 就复用（落后 main 先 rebase）；否则从当前 main
   新建 `feat/issue-N-<slug>`，worktree 放 .claude/worktrees/。
2. 按仓库实现约定实现：可行的接缝处用 tdd、常跑类型检查、最后全量测试。
3. 验证按仓库测试指南：逐一核对每条 @requires-* 声明，缺必需环境就是【卡住】，不得报完成。
4. 结局：
   - 确实需要业务决策（无人类选择就满足不了验收）→ 提交+推送部分成果，发 `🚦` 评论
     （问题 / 你的选项 / 分支名），把问题原文带回。
   - 任务不可能或环境阻塞 → 提交+推送，发 `🚫` 评论说明原因，返回。
   - 完成 → 测试绿，提交+推送。无人值守且已授权：合入 main、关闭自己的议题、评论结果（commit/冒烟）；
     值守或未授权：留 `待合入` 评论（分支+commit），不合入不关闭。返回。
5. 只动自己的议题和分支；父议题保持开，直到全部子议题完成。
```

## 四种返回

- **完成**：已合并+关闭。重算前沿。
- **待合入**（值守模式）：子代理完成但未合并。主代理向在场用户要**明确授权语句**；得到即由主代理执行合入+关闭，否则留在待合入。
- **提问**：子代理已推分支并发 `🚦`。把问题原文转述给用户（无需开仓库即可作答）。
  - 无人值守：继续其他可跑任务，不等待；用户稍后答复时**重启**该任务。
  - 值守：用户在场，停下等答复，答完立刻重启。
- **卡住**：子代理发了 `🚫`。重算前沿继续。

子代理空转/烧上下文：TaskStop 停掉重派。

## 重启（人类决策落地后）

用户在对话中答复转述的问题，或技能重跑发现**可续作**任务时，重启该子任务：

- 有环境则**复用**：分支 `feat/issue-N-*` 已推送、worktree 可能还在；落后 main 先 rebase。
- 没有则**创建**：从当前 main 新建。
- 派新子代理，简报同上，另附**人类的决策**，让它继续而非再问一遍。

重启就是一次普通派发，只是复用分支 + 简报带决策。

## 终局处理

前沿空时：

- **子议题全关闭** → 在父议题逐条评论任务结果汇总，然后关闭父议题。
- **否则** → 在父议题发交接评论，未完成任务一行一条：`#<n> — <状态> — <问题/分支在哪> — <下一步>`，等待决策、待合入、卡住分开列。父议题保持开。只起过步的就如实写，不编造进度。

## worktree 卫生

- worktree 放 `.claude/worktrees/`，以分支命名；建前 `git worktree list` 查复用，不重复建。
- 合并完成后 `git worktree remove` 清掉。串行下至多一个实现 worktree 活跃。

## 安全规则（高危动作及其闸门）

- 合入 main：仅在用户明确说出授权语句（如「满足测试要求的前提下，授权合并、关闭议题」）、且测试通过后。
- 关闭议题：仅在自己任务、仅随合并、仅在该次授权覆盖内。
- 推送、建删分支只发生在自己任务的 `feat/issue-N-*` 线上；不 force-push。
- 拿不准是否已授权 = 未授权。
